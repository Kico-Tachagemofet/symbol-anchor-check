# 可选作者牌意：读取与解读契约

公开安装默认关闭。`--meanings-pack <目录>` 启用，`--no-meanings` 显式关闭；
本地安装可使用不公开的 `meanings.local.json` 设置默认值。
具体命令和网站契约见
[牌意包 HANDOFF](https://github.com/Kico-Tachagemofet/kico-tarot-meanings/blob/main/HANDOFF.md)。

## 输入与复用

先检查 Phase 3 输出的 `meaning_pack.enabled`。开启时读取
`author_meanings` 中全部已加载正文；每个大牌位置通过 `author_meaning_ref`
指向对应条目。同一张牌的正文只存一次，但各位置分别按职责使用。
本包覆盖 22 张大牌，不为小牌、宫廷牌、奇迹牌补造作者牌意。

复用旧 Phase 3 包前，对照本次 DLC 选择与记录的包版本；不一致时用原始
已保存牌阵重新展开资料，不重新抽取。用户明确开启而资料缺失或加载失败时，
停在资料步骤，说明缺项；不能默默关闭后继续解读。

## Phase 3.5：完整正文先于场景候选

将当前大牌的完整作者正文与属性一起交给场域称重步骤，实际读完再构造整场。
正文中的动作、状态、条件分支和限制都属于语义材料；不能只抄元素标签或
挑一句贴合预设故事的话。逆位保留正文内容，再依本盘辨认表达怎样变化。
保留补牌仅澄清父位的范围。

Book T 对应、作者解释与当前场景推演分别标来源。作者正文参与解释，
不覆盖 `raw_correspondences` 或重算 `spread_synthesis`；正文与属性之间
若有不同侧重，说明差别怎样影响候选。它们属于同一张牌的资料，
不能当作两个独立抽取证据增加置信。

## Phase 4：内容必须改变可审查的推理

在分析记录中，为每张已加载大牌保留一行 `meaning_use`：
`card_id / 单牌版本 / 正文精确短引 / 本位支持、限制或无法区分的候选`。
引文来自 `author_meanings[card_id].text` 的叙述正文，不能用标题、标签、
版本号或“已加载”充当使用证据。

用这些具体支持与限制参与排除／保留／未定；不能为了证明使用过而强行排除。
正文未锁定的对象、时间、量级继续留白。后续 `narrowed_field`、answer
承接已经收束的结构；不要把整段牌意直接附在结尾当成解读。
已加载却未能用于本题的内容，明确写“未能落实”及原因。

结束前核对 `meaning_use` 是否覆盖所有已加载大牌，短引是否存在于正文，
answer 是否保留条件与精度。输出中简记包名与版本，完整校验值留在资料包。
此核对检验使用依据，不宣称脚本能够验证语义判断正确。
